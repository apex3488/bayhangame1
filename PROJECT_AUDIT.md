## 2. Решение по архитектуре

Источник истины — **существующая база Supabase** и её SQL-функции. Второй базы, второго API и копии экономики нет.

- **Mini App = та же игра** (тот же Next.js на Vercel), вход через новую страницу `/tg`.
- **Сервер Telegram** = две Supabase Edge Functions рядом с базой (HTTPS, постоянно, бесплатно; GitHub Pages и Vercel-статика для этого не нужны):
  `telegram-auth` (проверка initData, сессия, регистрация, привязка) и `telegram-bot` (webhook бота).
- Бот не считает деньги сам: `tg_call()` выполняет **те же** RPC игры (`get_my_snapshot`, `claim_daily`, `my_quests`…) от имени привязанного игрока.
- FastAPI/aiogram не добавлены: в проекте нет Python-backend, а замена стека без причины запрещена заданием. Edge Functions — штатная серверная часть Supabase.

Подробно: [docs/TELEGRAM.md](docs/TELEGRAM.md).

## 4. Найденные проблемы и что сделано

| Проблема | Решение |
|---|---|
| `X-Frame-Options: DENY` блокирует Telegram Web | заменён на CSP `frame-ancestors 'self' https://web.telegram.org https://*.telegram.org` (защита от встраивания чужими сайтами сохранена) |
| Нет связи Telegram ↔ аккаунт | таблица `telegram_accounts` (уникальны и игрок, и Telegram id), без автослияния по имени |
| Аккаунт из Telegram не может войти в браузере | логин `tg<id>` показан в профиле, пароль задаётся там же |
| Баланс устаревал при игре в двух местах | игра перечитывает состояние сервера при возврате на вкладку/в Mini App |
| Ошибка сети показывалась как «неизвестная ошибка» | отдельное сообщение «Нет связи с сервером игры» + кнопка «Повторить» на входе |
| `pgcrypto` в схеме `extensions` | исправлено миграцией 0024 (нашли тесты) |
